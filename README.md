# dsh-task-board

> DeepSeek Harness 的 AI 任务看板插件：每个工作区一块板，拖拽流转；任务交给 AI 在独立工作树里执行，
> AI 独立评审，通过后由人签字；支持 PR / 本地变更集、补丁导出与合并清理。

![看板 · 浅色](screenshots/01-desktop-light.png)

## 功能

- **侧栏入口 + 主面板**：左侧栏新增「看板」图标，点击切换到看板页面。
- **每个工作区一块板**：看板按工作区隔离，顶部项目切换器切换；每个工作区第一次打开是空板。
- **五条泳道**：待办 / 进行中 / AI 评审 / 待签收 / 已完成；卡片带状态徽标、轮次、执行模型、PR 号。
- **拖拽流转**：鼠标与触控拖拽，抬起浮层、目标泳道高亮、落位缺口；键盘 `Alt+←/→` 换栏（规则同拖拽），
  `Esc` 取消。只有「待办 / 受阻 / 失败 / 已取消」可以拖进「进行中」，其余换栏由 AI 与交付流程推进。
- **任务规格**：需求（标题 / 背景与约束 / 验收标准）、执行设置（执行模型 / 评审模型 / 预算 / 基线）
  折叠收纳；验收标准必填，缺失时不能开始。
- **AI 执行**：开始后，Host 为任务创建（或复用）独立任务副本（git worktree），起执行会话按需求干活；
  执行会话可以主动向人提问，也可以在完成时提交评审。
- **AI 评审回环**：执行完成后另起一个只读评审会话，能看变更、能跑白名单验证命令；评审打回时，意见
  自动回到执行会话返工（轮次 +1），达到轮数上限转为人工处理。
- **交付物**：评审通过后记录本地变更集（分支 / 基线 / 变更统计 / 补丁）；有远程仓库时可以「补建 PR」，
  也可以导出 `.patch`。
- **人工签收**：待签收任务可「通过签字」（带备注，可勾选签字后合并）或「打回返工」（意见回到执行会话）；
  已完成任务可「一键合并」（squash）或「清理工作树」。
- **需要你处理**：顶部收件箱聚合待回答、待签字、待补建 PR、交付失败、受阻、失败；任务抽屉里有问题原文
  和回答框。
- **详情抽屉**：先写需求，再交给 AI——验收必填；「AI 将收到的指令」可展开核对；执行记录只读展示每次
  执行会话、评审结论（含 `file:line` 的必须修复项）、交付物 / PR / 签字 / 失败原因；状态只读，主行动
  随状态变化；删除需二段确认。
- **归类**：优先级、截止日期、标签默认折叠，不打断写需求；搜索、标签筛选、优先级筛选实时更新。
- **非 Git 工作区引导**：工作区不是 Git 仓库时，顶部提示除「重新检测」外提供「立即创建 Git 仓库」——
  点击后插件会在该工作区新建一个会话并发送初始化指令（`git init` + 首次提交），完成后回到看板点
  「重新检测」即可开始执行任务。
- **实时更新**：页面可见且看板有正在推进的任务或抽屉打开时，每 2.5 秒同步一次 Host 数据；保存冲突会
  自动刷新并提示，不会静默覆盖别人的修改。
- **样例模式**：在面板地址后加 `?demo=1` 可加载一份中文样例板，便于先看效果（默认不再塞样例数据）。

## 安装

要求：**DSH >= 0.2.0 < 0.3.0**，Node >= 22。当前只通过 GitHub 分发。

### 方式一：Web UI（推荐）

1. 打开 DSH Web，左侧栏进入 **Plugins**；
2. 点 **Add plugin**；
3. 粘贴下面的 spec：

```
github:a285292107s/dsh-task-board
```

4. 点 **Install**，完成后点 **Enable now**。

### 方式二：命令行

```bash
dsh plugin --profile web add github:a285292107s/dsh-task-board
```

固定版本（推荐，避免上游变动）：

```bash
dsh plugin --profile web add github:a285292107s/dsh-task-board#v0.2.0
```

安装后重启 `dsh web`（或依赖 HMR 生效），左侧栏会出现「看板」入口。

### 升级 / 卸载

```bash
# 升级：先移除再安装新 tag
dsh plugin --profile web remove dsh-task-board
dsh plugin --profile web add github:a285292107s/dsh-task-board#v0.2.0

# 卸载
dsh plugin --profile web remove dsh-task-board
```

> Git 安装的插件不会出现在 Plugins 页的「Versions / Update」列表里，升级需要按上面的方式重装。

## 使用

1. 顶部项目切换器选择工作区；点「新建」或按 `N` 创建任务。
2. 在抽屉里写清**标题 + 背景 + 验收标准**。需要指定模型时可填「执行模型 / 评审模型」（留空用宿主
   默认，格式 `provider/model`，即宿主里已配置的服务提供方与模型名）；预算与基线默认跟随看板默认值。
3. 点「开始执行」，或把卡片拖入「进行中」。前提：工作区是 Git 仓库且至少有一次提交，并且不是另一个
   工作树副本；工作区有未提交改动时，需要勾选「以当前 HEAD 为基线，忽略未提交改动」。
4. AI 在独立任务副本里执行，完成后自动进入 AI 评审。评审打回会自动返工；达到轮数上限则转为人工处理。
   AI 需要你补充信息时，抽屉会显示问题，回答后会回到原会话继续。
5. 评审通过后进入「待签收」。在抽屉里核对执行记录、评审意见与交付物：
   - **通过签字**：可写备注；勾选「签字后合并到根仓库当前分支」则先合并再标完成。
   - **打回返工**：备注作为返工意见回到执行会话。
   - **补建 PR**：有远程仓库时可把任务分支推上去并创建/绑定 PR。
   - **导出补丁**：下载 `.patch`。
6. 已完成任务可「一键合并」（squash 到根仓库当前分支，要求根仓库干净）或「清理工作树」（移除任务
   副本与分支）。取消的任务也可以清理。

看板本身不要求工作区是 Git 仓库；只有「执行」相关动作需要。工作区还不是 Git 仓库时，看板顶部会给出
「立即创建 Git 仓库」：插件在该工作区新建一个会话并让 AI 执行 `git init` 与首次提交，完成后回到看板点
「重新检测」即可开始执行任务。

## 数据与隐私

- 看板数据保存在 `$DSH_HOME/task-board/<workspaceId>.json`，状态变更另记一份本机审计日志
  `<workspaceId>.audit.jsonl`；只在本机。
- 插件不上传任何数据、不采集遥测；网络请求只发生在你主动触发模型执行、AI 评审或创建 PR 时。
- 每个任务的工作树建在仓库内 `.agents/worktrees/`；合并、推送与清理都是你显式触发的动作。
- 每次执行/评审记录的 token 用量仅写入本机执行记录，当前不会因预算自动中止。
- `/task-board-api/git` 只允许读取已注册工作区内的路径，工作区外返回 403。

## 开发

纯 JavaScript，无构建步骤：

```bash
node --check index.js
node --check client.js
```

本地联调：

```bash
# 1) 建一个独立 dev profile（复制官方 web 模板）
dsh --profile kanban-dev --from-default-profile web --dump-config

# 2) 把本仓库链接进去
dsh plugin --profile kanban-dev add /absolute/path/to/dsh-task-board

# 3) 起独立实例
dsh --profile kanban-dev --port 3081
```

修改 `client.js` 后刷新页面；修改 `index.js` 后重启 dev 实例。
